## 3. 共通CLI動作

### 3.1 終了コードと出力先

- 正常終了とhelp表示は終了コード`0`とする。
- 引数不正、対象メモなし、読み込み失敗、保存失敗は終了コード`1`とする。
- コマンドの正常な結果と全体helpは標準出力へ出す。
- `memo <command> --help`の対象コマンドhelpは、実装済みの動作を維持して標準エラーへ出す。
- エラーと、エラーに伴うusageは標準エラーへ出す。
- 失敗した更新操作では、保存済みメモを変更しない。

### 3.2 引数とオプション

- 通常は必須の位置引数を先に置き、その後にオプションを置く。
- `--`を使う場合は、オプション、`--`、位置引数の順に置き、`--`以降を位置引数として扱う。
- 未定義オプション、位置引数の過不足、オプション値の不足はエラーとし、コマンドのusageを表示する。
- `memo help`、`memo -h`、`memo --help`は全体helpを表示する。
- `memo <command> --help`は対象コマンドのhelpを表示する。
- オプション値として文字列`--`を渡す場合は、v0.2では`--body=--`のように`=`形式を使う。独立した引数の`--`はオプション終端として扱う。

### 3.3 ID

- IDの位置引数は10進整数として解析する。
- 整数として解析できない値は入力エラーとする。
- 存在しないIDは`memo not found: <id>`を標準エラーに出す。
- IDは1以上の整数とし、0以下は入力エラーとする。
- 先頭が`-`のIDは通常の構文ではオプションとして解釈される。`--`以降に置いて位置引数として解釈された場合も、正の整数ではないため入力エラーとする。

## 4. メモの追加

構文:

```text
memo add <title> [--body <body>]
```

- `title`は必須とする。空文字または空白文字だけのタイトルはエラーとする。
- 許可されたタイトルの先頭・末尾の空白は、入力されたまま保存する。
- `--body`を省略した場合、本文は空文字として保存する。
- 本文には空文字、空白、改行を含む文字列を保存できる。
- 新しいIDは、保存済みメモの最大IDに1を加えた値とする。メモがない場合は1とする。
- `CreatedAt`と`UpdatedAt`には同じ追加時刻を設定する。
- 保存した本文は`show`で表示し、`search`の検索対象に含める。

この動作は#24で実装済みであり、Specでは既存の動作を確認対象として扱う。

## 5. メモの編集

構文:

```text
memo edit <id> [--title <title>] [--body <body>]
```

- `--title`だけ、`--body`だけ、または両方を指定できる。
- `--title`と`--body`を両方省略した場合はエラーとし、保存しない。
- 指定していない項目は変更しない。
- `--title`に空文字または空白文字だけを指定した場合はエラーとし、保存しない。
- 許可されたタイトルの先頭・末尾の空白は、入力されたまま保存する。
- `--body ""`は有効な指定として扱い、本文を空文字へ変更する。
- 本文には空白、改行を含む文字列を保存できる。
- 対象IDが存在しない場合はエラーとし、保存しない。
- 編集しても`ID`と`CreatedAt`は変更しない。
- 編集が成立した場合、`UpdatedAt`を編集時刻へ変更する。
- 指定値が保存済みの値と同じ場合も有効な編集操作とし、`UpdatedAt`を編集時刻へ変更する。
- 正常終了時には標準出力へ何も出さない。

## 6. 保存先の決定

- 環境変数`MEMO_PATH`に空でない値が設定されている場合、その値を保存先として使う。
- `MEMO_PATH`が未設定の場合は`~/.memo/memos.json`を使う。
- `MEMO_PATH`が空文字の場合は、未設定の場合と同じく`~/.memo/memos.json`を使う。
- 保存先が`~/`で始まる場合、`~`を実行ユーザーのホームディレクトリへ展開する。
- `~`だけ、および`~user/`形式は展開しない。
- 相対パスは実行時のカレントディレクトリを基準として使用できる。
- `MEMO_PATH`で別のファイルを指定した場合、既定ファイルを読み書きしない。
- コマンドラインオプションによる保存先指定はv0.2の対象外とする。

## 7. JSONストレージ

### 7.1 データ形式

JSONファイルの最上位はメモの配列とし、各メモは次のフィールドを持つ。

| JSONフィールド | 型 | 意味 |
|---|---|---|
| `id` | integer | メモを識別するID |
| `title` | string | タイトル |
| `body` | string | 本文 |
| `created_at` | RFC 3339形式のstring | 作成日時 |
| `updated_at` | RFC 3339形式のstring | 更新日時 |

- JSON文書は、最上位にメモの配列を一つだけ持つ。空配列は有効とする。
- 最上位の`null`、配列以外の値、および配列の後に空白以外の別の値が続く文書は不正とする。
- 配列の各要素はオブジェクトとし、`id`、`title`、`body`、`created_at`、`updated_at`をすべて持つ。フィールド欠落、型不一致、RFC 3339として解析できない日時は不正とする。
- 未知フィールド、重複キー、IDの重複、タイトルやIDの値の妥当性など、上記以外のスキーマ検証はv0.2の対象外とする。
- v0.1.0が保存したJSONを移行操作なしで読み込める。
- v0.2で保存したJSONは同じフィールド名と意味を維持する。
- 読み込み順と保存済みIDを維持する。

### 7.2 読み書き

- 保存先ファイルが存在しない場合は、メモ0件として扱う。
- 保存時に親ディレクトリが存在しなければ作成する。
- JSONが不正な場合、読み込みに失敗したことを標準エラーへ出し、終了コード`1`とする。ファイルは変更しない。
- ファイルまたは親ディレクトリの権限などにより読み書きできない場合、操作に失敗したことを標準エラーへ出し、終了コード`1`とする。
- 保存は同じディレクトリの一時ファイルへ全内容を書き込み、成功後に保存先と置き換える。保存途中でエラーになった場合、既存ファイルを変更しない。
- 複数プロセスからの同時更新制御はv0.2の対象外とする。

## 8. 既存コマンドと文書

- `add`、`list`、`show`、`search`、`delete`の構文と正常系の出力を維持する。
- `search`は大文字・小文字を区別し、タイトルまたは本文にキーワードを含むメモを保存順に表示する。
- `show`はID、タイトル、本文、作成日時、更新日時を表示する。
- `list`はID、タイトル、作成日を保存順に表示する。
- IDを必要とするコマンドで0以下を入力エラーとすることは、D-02で明示的に決めたv0.2の入力検証変更とする。
- READMEには`add --body`、`edit`、`MEMO_PATH`、既存JSONとの互換性、v0.2の完成条件を記載する。
- v0.2.0のリリースノートを用意する。

## 10. 決定事項

D-01からD-04は、プロジェクト所有者が2026-09-06に推奨案を採用した。

### D-01 同じ値を指定した編集

例: 現在のタイトルが`Title`のときに`memo edit 1 --title "Title"`を実行する。

- **採用**: 有効な編集操作として保存し、`UpdatedAt`を更新する。
- **理由**: 「指定された編集操作の実行時刻」という単純な規則になり、実装と説明が一貫する。
- **不採用案**: 変更なしとして保存せず、`UpdatedAt`も維持する。実質的な変更時刻を表せる一方、全指定項目を既存値と比較する分岐が必要になる。

### D-02 0以下のID

例: `memo show 0`、`memo show -1`、`memo edit --body "x" -- -1`。

- **採用**: IDを正の整数と定義し、0以下を入力エラーとして拒否する。
- **理由**: 生成されるIDの範囲と入力規則が一致する。
- **影響**: `0`の既存動作は変わる。先頭が`-`のIDは引数解析で拒否される場合と、`--`以降でID検証により拒否される場合があるが、どちらも入力エラーとする。
- **不採用案**: 既存動作を維持する。互換性を優先できる一方、0と負数で見え方が揃わない。

### D-03 空のMEMO_PATH

例: `MEMO_PATH= memo list`。

- **採用**: 未設定と同じく`~/.memo/memos.json`を使う。
- **理由**: 単純な設定ミスでも既定動作へ戻り、空パスをファイル処理へ渡さずに済む。
- **不採用案**: 設定エラーとして終了コード1にする。空値を検出できる一方、未設定と空値で挙動が変わる。

### D-04 edit成功時の出力

- **採用**: 標準出力へ何も出さない。
- **理由**: 既存のaddとdeleteの成功時動作に揃えられる。
- **不採用案**: 更新したIDなどの確認メッセージを標準出力へ出す。成功を確認しやすい一方、新しい出力形式の決定が必要になる。

## 11. 実装前に合意する責務

- `cmd/memo`は、環境から保存先を取得し、依存関係を組み立ててCLIを実行する。
- `internal/cli`は、コマンドの振り分け、引数検証、入出力、メモ操作とストレージの連携を担当する。
- `internal/memo`は、編集対象の探索、値の更新、作成日時・更新日時の規則を担当する。
- `internal/storage`は、パス展開とJSONファイルの読み書きを担当する。
- 環境変数の取得と既定値選択をどの関数へ分けるかなど、局所的な構造はPlan・実装で決める。
