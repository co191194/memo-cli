## 3. 背景、利用者、利用場面

### 背景

v0.1では、ローカルのJSONファイルにメモを保存し、追加・一覧・詳細表示・検索・削除を行えるMVPを構築した。v0.2では、本文を含むメモを作成・編集でき、用途や環境ごとに保存先を切り替えられるようにして、日常的な利用に必要な操作を揃える。

このプロジェクトにはGoとCLI開発を学ぶ目的もある。v0.2の残作業では、人間が要件・仕様・実装上の主要な判断を行い、AIが整理・提案・調査・検証を支援する方法を試行する。

### 利用者

- ターミナルで個人用メモを管理するプロジェクト所有者
- memo-cliを題材にGo、CLI設計、テストを学ぶプロジェクト所有者

### 主な利用場面

1. タイトルと本文を指定してメモを保存し、後から詳細表示や検索で利用する。
2. 保存済みメモのタイトル、本文、または両方を修正する。
3. 用途や実行環境に応じて、既定とは異なるJSONファイルを保存先に選ぶ。
4. 既存のv0.1データとコマンドを維持したままv0.2へ移行する。

## 5. v0.2全体の成功条件

次のすべてを満たしたとき、v0.2の要件を満たしたと判断する。

1. R-01からR-07に対応する受け入れ基準がSpecに定義され、検証済みである。
2. v0.2マイルストーンに含まれる実装・テスト・利用者向け文書のIssueが完了している。
3. 既存JSONデータを移行操作なしで利用でき、既存MVPコマンドの互換性が保たれている。
4. GitHub Actionsで書式、静的解析、race detector付きテスト、ビルドが成功している。
5. プロジェクト所有者が、v0.2で実現する内容、対象外、主要な仕様判断、確認方法を説明できる。

R-08の試行結果はv0.2の開発手法を評価する材料とする。試行結果そのものをCLIのリリース品質とは扱わない。

## 6. 対象外

v0.2では次を実装しない。

- タグ・カテゴリ機能
- SQLite対応
- TUI・Web UI
- Markdownのimport・export
- 外部エディタ連携
- グローバルな `--data-file` オプション
- データ暗号化、複数利用者対応、ネットワーク同期
- 全既存機能の詳細な内部設計書の作成

## 7. 制約

- メモはローカルのJSONファイルに保存する。
- 既存のJSONフィールドとその意味を維持する。
- 既存のMVPコマンド形式と外部から見える動作を、明示した仕様変更なしに壊さない。
- 新しい本番依存パッケージは、プロジェクト所有者の事前承認なしに追加しない。
- Requirement、Spec、Plan、実装、受け入れの承認を推測せず、プロジェクト所有者の明示した判断を記録する。
- #35では実装コードとREADMEの全面更新を行わない。

## 8. 学習目標

1. 要望を、対象外と成功条件を含む要件へ整理し、Issue・仕様・受け入れ基準まで追跡できるようにする。
2. Requirementの「何を・なぜ」と、Specの「外部から見てどう動くか」、実装方法を区別して判断する。
3. CLIの正常系・異常系・境界条件について代替案と影響を比較し、期待結果をテスト可能な形で決める。
